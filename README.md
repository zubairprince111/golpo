# Whispers of Place

PROJECT: A MAP OF US

Build a premium, editorial, map-first storytelling web application called:

A MAP OF US

The product is a living map of Bangladesh where people leave memories, stories, thoughts, feelings, and meaningful moments attached to real geographic locations.

IMPORTANT:

The attached reference image is the PRIMARY VISUAL REFERENCE for this project.

Treat the reference image as the visual north star.

Do not reinterpret it into a generic modern SaaS design.

Do not simplify it into a generic dashboard.

Do not replace the visual language with common AI-generated UI patterns.

The finished product should feel like the same design family as the reference image:

quiet, sophisticated, editorial, monochromatic, literary, minimal, human and highly polished.

==================================================

1. CORE PRODUCT PHILOSOPHY

==================================================

The map is not a feature of the product.

THE MAP IS THE PRODUCT.

Stories live on the map.

A user should be able to enter the experience, explore Bangladesh geographically, discover a marked location, tap it, and read the story attached to that exact place.

The experience should feel like discovering a page from a stranger's life.

The product should NOT feel like:

- a social media platform

- a traditional blog

- a content feed

- a startup landing page

- a SaaS dashboard

- Google Maps with stories attached

- a travel website

- an AI-generated template

It should feel like:

- a digital archive

- a literary map

- a contemporary editorial publication

- a quiet collection of human memories

- a beautifully designed interactive book

The emotional goal is:

"I don't know this person, but somehow I understand this place differently now."

==================================================

4. TYPOGRAPHY

==================================================

Typography is extremely important.

The product should feel editorial and literary.

Do NOT use the typical generic combination of:

Inter + generic serif

without considering the overall personality.

Use a sophisticated editorial serif for story content and a restrained modern sans-serif for interface elements.

Suggested direction:

Interface:

Geist / Inter / Suisse-style sans-serif

Editorial content:

Newsreader / Source Serif 4 / another sophisticated literary serif

However, choose the actual available web fonts that best reproduce the attached reference image.

The story typography should feel like a printed novel.

Large story headlines should have:

- generous line height

- strong contrast

- restrained width

- beautiful letter spacing

- significant whitespace

Body text should be highly readable.

Do not make every text element large.

Use hierarchy.

Small metadata should be understated.

For Bangla content:

Make sure the chosen Bengali-compatible typography renders correctly.

The system must gracefully support:

Bangla

Banglish

English

mixed Bangla + English

Do not allow Bengali text to look visually broken or like a fallback font.

5. LANDING PAGE

==================================================

The landing page should be extremely minimal.

Do NOT build a conventional marketing landing page.

Do NOT add:

- feature grids

- pricing

- testimonials

- FAQ

- newsletter signup

- large footer sections

- multiple marketing sections

- unnecessary cards

The landing page should feel almost like the opening page of a book.

Composition:

A MAP OF US

Stories live where they happened.

[ Explore the Map ]

The map/geographic silhouette of Bangladesh can exist very subtly as part of the background or composition.

It should not look like a decorative illustration.

It should feel like cartography.

The page should have enormous breathing room.

The user should immediately understand that the map is the central experience.

==================================================

6. EXPLORE MAP TRANSITION

==================================================

When the user clicks:

Explore the Map

DO NOT immediately show the map.

There must be an intentional transition.

This is an important part of the brand experience.

The transition should feel cinematic but restrained.

Approximately:

1. User clicks Explore the Map

2. Landing content begins fading away

3. The interface becomes quiet

4. A subtle loading/introduction state appears

5. The map begins to resolve

6. The Bangladesh map fades/zooms into view

7. The user enters the map

The transition should feel intentional rather than like a normal loading spinner.

Avoid generic loading spinners.

Use typography, opacity and subtle motion.

The entire transition should be approximately 1.5 to 3 seconds.

It should never feel slow or frustrating.

==================================================

7. MAP

==================================================

Use LEAFLET for the actual map.

Do NOT use Google Maps.

Do NOT use Mapbox unless absolutely necessary for tiles.

The map must be the dominant element of the application.

The map should visually resemble the attached reference image.

Use a restrained monochromatic/light cartographic style.

Bangladesh should be clearly recognizable.

The map should support:

- pan

- zoom

- click/tap markers

- marker clustering

- location selection

- smooth transitions

- responsive interaction

Map labels should remain elegant and understated.

Do not overload the map with labels.

Do not make it visually busy.

==================================================

8. STORY MARKERS

==================================================

Do not use generic red Google Maps pins.

Story markers should be subtle monochrome points.

Think of them as small pieces of punctuation placed on the map.

Possible visual language:

- small black dots

- thin rings

- subtle halos

- understated clustered numbers

Markers should feel like part of the cartography.

When a marker is selected:

- it should become visually emphasized

- the map should gently focus on it

- the corresponding story should open

- the transition should be smooth

Do not use flashy animations.

Do not use bouncing pins.

==================================================

9. STORY CLUSTERS

==================================================

If multiple stories exist in a small geographic area, cluster them.

Clusters should not look like generic map clustering components.

Use minimalist circular indicators with numbers.

Example:

2

5

12

The visual treatment should be monochrome and editorial.

As the user zooms in, clusters should gracefully separate into individual story markers.

==================================================

10. STORY READING EXPERIENCE

==================================================

This is the most important interaction in the application.

When the user taps a location, the associated story should open while keeping the map visible.

The user should never feel like they left the map.

DESKTOP:

Use a large editorial reading panel positioned over or beside the map.

The map should remain visible.

The panel should resemble a beautifully typeset page rather than a social media post.

Example structure:

A7K29

The exact copy is placeholder content only.

The visual structure is what matters.

The story panel should have:

- beautiful typography

- generous margins

- clear hierarchy

- restrained metadata

- minimal controls

- no excessive UI

- no reaction-count obsession

The story is the hero.

Avoid excessive corner radius.

Primary action:

No image attachment.

No video upload.

No gallery.

No hashtags.

No unnecessary social features.

==================================================

14. ACCOUNT REQUIREMENT

==================================================

Users MUST create an account or log in before publishing a memory.

This is for:

- security

- accountability

- abuse prevention

- moderation

- ownership of private memories

However, the user's real identity should NOT be displayed publicly.

Every user automatically receives a unique anonymous ID.

Example:

A7K29

or:

US-4Q7F

The public sees only the anonymous ID.

The database retains the actual account association.

This means:

PUBLIC:

A7K29

BACKEND:

auth_user_id -> A7K29

Never expose:

- email

- real name

- account ID

- private profile data

unless explicitly required by future product functionality.

==================================================

15. PUBLIC / PRIVATE MEMORIES

==================================================

Every memory must have a visibility state.

PUBLIC:

The story appears on the public map and can be discovered by other users.

PRIVATE:

The story is visible only to the owner inside their personal memory archive.

Private memories must NEVER appear on the public map.

Users should be able to clearly understand this choice before publishing.

Use simple language.

Avoid complicated permission UI.

==================================================

32. WHAT SHOULD FEEL SPECIAL

==================================================

Spend most of the design effort on these five experiences:

1. Entering the map

2. Discovering a memory marker

5. Returning to a private memory through the map

33. FINAL DESIGN PRINCIPLE

==================================================

A Map of Us should feel like:

A quiet archive of human experiences.

A place where memories remain attached to the places that created them.

The interface should disappear when the story begins.

The map should disappear when the user becomes absorbed in the story.

The user should move naturally between:

PLACE

↓

MEMORY

↓

STORY

↓

PLACE

That loop is the product.

Build the frontend with extreme attention to typography, spacing, map composition, interaction design, responsiveness and subtle motion.

Use the attached reference image as the visual source of truth.

Do not redesign it into something else.

Build a polished, production-quality interpretation of this exact visual language.
